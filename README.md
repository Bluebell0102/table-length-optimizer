# 表格长度优化

给飞书文档和 Markdown 里的每张表，在**列宽**和**行高**之间选最优比：内容短的表不硬拉宽，长说明多的表才加宽，尽量少折行、不留孤字。

一个 Python 脚本 [`表格长度优化.py`](表格长度优化.py)，无第三方依赖。

---

## 1. 解决什么问题

用 Markdown 导入飞书文档时，列宽由飞书按内容粗估，常见两个毛病：

- **表宽有长有短**：有的表只占页面大半，有的拉满正文宽，右边缘参差不齐。
- **列宽不按内容分**：只写几个字的短列占着宽度，写长句的列被挤窄，一格折成三四行，整行被撑高。

## 2. 原理：在宽和高之间取最优比

不是把所有表统一拉满，而是每张表单独算，分三步：

1. **画曲线**：从每列的下限起步（表头不折行、8 个字以内的短格不拆、英文数字串不拆、最窄 64px），每次把宽度加给「每 px 能少折最多行」的那一列，得到一条「表格宽度 → 表格高度」曲线。
2. **取最优点**：在曲线上取「高度 + 宽度 × 比价」最小的一点。比价由 `--ratio` 定，默认 150，意思是**加宽 150px 至少要少折 1 行才值得加**，换不回就停。
   - 内容短的表停在刚好一行放下的宽度；
   - 长说明多的表才会拉到满宽。
3. **微调**：在选定宽度上做列间挪宽度，取折行最少、孤字最少的分法。

### 排版模型

| 参数 | 值 | 说明 |
|---|---|---|
| 中文字宽 | 14px | 半角 7px；≥ × 【】 等歧义宽度符号按全角算 |
| 单元格内边距 | 28px | 左右内边距 + 边框，含估算余量 |
| 行高 | 24px / 行字 | 每行另加 18px 上下内边距 |
| 断行 | 逐词模拟 | 英文 / 数字串整体换行；开头括号粘后字、收尾标点粘前字（避头尾） |
| 孤字 | 罚 0.4 行 | 折行后末行只剩 1～3 个字 |
| 表格最宽 | 738px | 飞书标准页宽的正文满宽；宽版页面用 `--max-width 938` |

## 3. 怎么用

### 准备

- Python 3.8+
- 处理飞书文档需要 [lark-cli](https://github.com/larksuite/cli)（npm 包 `@larksuite/cli`）并已用个人身份登录（`--as user`）；只处理 Markdown 不需要。

### 命令

默认**只出报告不改**，确认后加 `--apply` 才写入。

```bash
# 飞书单篇文档 / 知识库页面（链接或 docx token 都行）
python3 表格长度优化.py https://xxx.feishu.cn/docx/<token>
python3 表格长度优化.py https://xxx.feishu.cn/docx/<token> --apply

# 飞书整个文件夹（--recursive 连子文件夹）
python3 表格长度优化.py https://xxx.feishu.cn/drive/folder/<token> --recursive

# Markdown：默认把 | 表格改写成带列宽的表格标签（飞书导入、支持 HTML 的预览器都认）
python3 表格长度优化.py 文档.md --apply -o 文档.飞书.md

# Markdown：保留 | 表格，只把源码按中英文宽度对齐
python3 表格长度优化.py 文档.md --md-format pipe --apply
```

### 参数

| 参数 | 默认 | 作用 |
|---|---|---|
| `--apply` | 关 | 写回；不加只出报告 |
| `--ratio` | 150 | 加宽多少 px 至少要省 1 行才加宽。调小 → 表更窄更高；调大 → 表更宽更矮 |
| `--max-width` | 738 | 表格最宽 |
| `--recursive` | 关 | 文件夹连子文件夹一起处理 |
| `--md-format` | feishu | `feishu` = 带列宽的表格标签；`pipe` = 保留 \| 表格只对齐源码 |
| `-o` | 原地覆盖 | 只处理一个 .md 时写到别的文件 |

### 它会改什么、不改什么

- **飞书**：只改每张表的列宽，不动任何文字；改坏了可在飞书「历史版本」回退。
- **Markdown（feishu 格式）**：只把 `|` 表格换成等价的表格标签，粗体、斜体、删除线、行内代码、链接、`<br>` 都保留；正文其他行一字不改。
- **重复运行不会来回变**：现状已经不差就不动。

### 报告怎么看

以 [`示例/示例.md`](示例/示例.md) 为例：

```text
《示例.md》 Markdown 表格 3 张（输出格式：feishu）
  表  1 状态 / 说明（4×2）
        宽 238px、高约 168px（4 行字）   列宽 [70, 168]
  表  2 名词 / 解释（4×2）
        宽 637px、高约 168px（4 行字）   列宽 [98, 539]
  表  3 城市 / 气候特点 / 适合出行 / 平均气温 / 备注（3×5）
        宽 679px、高约 150px（4 行字）   列宽 [70, 252, 161, 84, 112]
```

- 短表只有 238px 宽，长说明表才拉到 637px，每张表的宽度按内容定。
- 飞书文档的报告会多一段「改前 → 改后」，不需要改的表标「（不变）」。
- 末尾 `⚠` 是内容层面的建议：超过 15 行建议拆表或挪附录；只有 1 行数据建议改成一句话；某格折到 6 行及以上建议长说明挪到表外；列多到塞不下建议拆表。

[`示例/`](示例/) 里有原始 Markdown 和两种输出（`示例.飞书.md` / `示例.对齐.md`），可以直接对照。

## 4. 飞书接口注意事项

- 批量改列宽用 `PATCH /open-apis/docx/v1/documents/<doc>/blocks/batch_update`，**同一张表在一次请求里只能出现一次**，否则报 `1770001 invalid param`。脚本按列序号分轮发，每轮最多 100 条。
- 读列宽要 `docs +fetch --doc-format xml --detail with-ids`；默认的 simple 模式不带列宽。
- Markdown 导入（`docs +create` / `docs +update --doc-format markdown`）认 `<table><colgroup><col width="N"/></colgroup>…</table>`，列宽原样落地。
- 飞书接口偶发 `network/transport … EOF`，脚本自动重试 3 次（设列宽是幂等的，重试安全）；写入后回读失败会提示重跑一次核对。

## 5. 已知限制

- 列宽按字数估算，不是真实渲染。表格已经满宽、内容又很密时，偶尔仍会剩一个字单独一行。
- 各家 Markdown 预览器对 `<col width>` 的支持程度不一，以飞书导入效果为准。
- 飞书旧版文档（doc，非 docx）、电子表格、多维表格不处理：单篇链接会提示跳过，文件夹里直接略过。
- 合并单元格按跨列 / 跨行估算；单元格里的图片按约 160px 宽占位。
